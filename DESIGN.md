# DRAFTED — MVP Design

## 1. Purpose

DRAFTED is a deliberately small Chrome extension for one problem:

> You can write once you start, but you keep postponing the moment of contact with the manuscript.

Instead of asking the user to schedule a writing session, DRAFTED removes that decision. Once per day, at a random eligible time, it opens a configured document and requires a small amount of physical interaction with it before releasing the tab.

The extension must stay playful, local, and intentionally stupid.

It does not evaluate prose. It does not measure productivity. It does not care whether the user writes 300 useful characters or presses Space 300 times.

The behavioral target is **starting**, not producing.

---

## 2. MVP principles

1. **Ambush, don't remind.**  
   The activation time is random and hidden from the user.

2. **Require contact, not quality.**  
   Progress is measured in keystrokes, not words, characters, or meaningful edits.

3. **Make escape possible, but mildly annoying.**  
   Switching tabs returns the user to the drafted tab. Quitting Chrome, changing browser/window, or disabling the extension remains possible.

4. **Do not inspect writing.**  
   Never store key values, document text, clipboard data, selections, or page content.

5. **Stay tiny.**  
   No accounts, cloud sync, streaks, points, achievements, AI, statistics dashboard, or Chrome Web Store release in v1.

---

## 3. User flow

### 3.1 First run

On installation, open the settings page.

The user configures:

- Target URL
- Keystroke quota
- Excluded time ranges
- Enabled / disabled state

Defaults:

- Target URL: empty
- Keystroke quota: `300`
- Excluded ranges: none
- Enabled: true once a valid URL has been saved

No drafting session is scheduled until a valid target URL exists.

### 3.2 Daily scheduling

The MVP triggers at most **once per local calendar day**.

The service worker chooses a random future minute that:

- is outside every excluded time range;
- is later than the current time if scheduling for today;
- belongs to the user's local time zone.

If no eligible minute remains today, choose a random eligible minute tomorrow.

The exact scheduled time should not be shown in the UI. The UI may simply say `ARMED`.

Whenever Chrome starts, settings change, or an alarm fires in an invalid time range, recalculate the next eligible random activation.

If Chrome was closed when an old alarm should have fired, do not immediately fire a stale ambush on startup. Recalculate from the current time instead.

### 3.3 Drafting session

When the alarm fires:

1. Create a new tab containing the configured target URL.
2. Record the tab ID and window ID as the active drafting session.
3. Inject the DRAFTED content script once the page is available.
4. Show a temporary full-page visual overlay:

   **YOU HAVE BEEN DRAFTED**  
   **{quota} KEYSTROKES TO DISCHARGE**

5. After the intro, retain a small non-blocking HUD showing remaining keystrokes.
6. Count qualifying `keydown` events.
7. When remaining keystrokes reach zero:
   - mark the session complete;
   - stop redirecting tab changes;
   - remove the HUD;
   - show `DISCHARGED.` briefly;
   - mark today as completed;
   - schedule the next eligible day.

## 4. Keystroke rules

The counter exists to create physical contact with the document, not to police useful writing.

### Count

Count one hit for each `keydown` event that:

- is not generated by key repeat (`event.repeat === false`);
- is not a pure modifier key such as Shift, Control, Alt, Meta, CapsLock, or Fn.

Examples that count:

- letters
- numbers
- punctuation
- Space
- Enter
- Backspace
- Delete
- arrow keys
- Tab

This is intentionally permissive.

### Never store

The implementation must never persist or transmit:

- `event.key`
- typed characters
- text content
- document contents
- clipboard contents

The content script should emit only a generic `keystroke` message or numeric increment.

---

## 5. Tab enforcement

Chrome extensions cannot truly prevent a user from selecting another tab before the browser performs the switch. The MVP therefore uses **soft enforcement**.

### Switching tabs

While a drafting session is active:

- listen to `chrome.tabs.onActivated`;
- if the newly active tab is not the drafted tab in the drafted window, reactivate the drafted tab;
- once returned, ask the content script to replay the warning overlay with the current remaining count.

Suggested warning copy:

**YOU ARE STILL DRAFTED**  
**{remaining} KEYSTROKES TO DISCHARGE**

A small internal guard should prevent the extension's own corrective tab activation from creating an event loop.

### Closing the drafted tab

While the session is active:

- listen to `chrome.tabs.onRemoved`;
- if the drafted tab is closed, reopen the target URL;
- preserve the current keystroke count;
- assign the new tab ID to the current session;
- re-inject the content script and warning overlay.

### Deliberate escape hatches

The MVP does **not** attempt to prevent:

- quitting Chrome;
- switching to another browser;
- switching to another Chrome window;
- disabling or uninstalling the extension;
- killing the Chrome process.

Do not escalate beyond tab-level enforcement. DRAFTED should remain funny, not hostile.

## 6. Session persistence

Use two storage layers.

### `chrome.storage.local`

Persistent settings and daily scheduling metadata:

```js
{
  settings: {
    enabled: true,
    targetUrl: "https://docs.google.com/...",
    keystrokeQuota: 300,
    excludedRanges: [
      { start: "06:00", end: "14:00" },
      { start: "23:00", end: "07:00" }
    ]
  },
  lastDraftDate: "2026-09-01"
}
```

Excluded ranges must support crossing midnight.

### `chrome.storage.session`

Current live session only:

```js
{
  activeSession: {
    tabId: 123,
    windowId: 45,
    targetUrl: "https://docs.google.com/...",
    quota: 300,
    count: 127,
    remaining: 173,
    startedAt: 1788255000000
  }
}
```

Using session storage means quitting Chrome ends the coercive session. That is intentional.

`lastDraftDate` should be written when an ambush begins so restarting Chrome does not immediately trigger another ambush the same day.

---

## 7. Settings UI

Keep settings to one simple page.

### Fields

**Target URL**
- `<input type="url">`
- required before arming

**Keystrokes to discharge**
- `<input type="number">`
- default `300`
- suggested bounds: `1`–`10000`

**Excluded hours**
- repeatable rows containing `start` and `end` time inputs
- add/remove range buttons
- ranges may cross midnight

**Enabled**
- one checkbox or toggle

### Status

Display only a coarse state:

- `UNCONFIGURED`
- `DISARMED`
- `ARMED`
- `DRAFTED`

Do not reveal the random activation time.

Optional but useful for development: a `TEST DRAFT NOW` button. Keep it visually secondary and clearly marked as a test control.

---

## 8. URL permissions

DRAFTED should not request permanent access to every website by default.

Recommended Manifest V3 approach:

- request `storage`, `alarms`, `scripting`, and `tabs` permissions;
- declare broad web origins under `optional_host_permissions`;
- when the user saves the Target URL, request access only to that URL's origin through `chrome.permissions.request()` from the user gesture;
- inject the content script only into the drafted tab.

Example origin conversion:

```text
https://docs.google.com/document/d/abc/edit
→ https://docs.google.com/*
```

If runtime host permission proves disproportionately troublesome for the first prototype, using `<all_urls>` is acceptable during local development, but the public GitHub version should prefer optional origin access.

---

## 9. Google Docs compatibility

Google Docs is a required MVP target.

The implementation should first try document-level key capture from an injected content script using the capture phase:

```js
window.addEventListener("keydown", handler, true);
```

Because rich editors can use frames or unusual event plumbing, this must be tested in an actual Google Docs document.

If top-frame capture is insufficient:

- inject into all accessible frames with `chrome.scripting.executeScript({ target: { tabId, allFrames: true } })`;
- centralize the numeric counter in the service worker so multiple frames cannot maintain divergent counts.

Guard against duplicate counting if the same physical event is observed by more than one injected context.

The extension must not depend on Google Docs DOM structure, editor class names, or document text. Only keyboard events should matter.

## 11. Background service worker responsibilities

`background.js` owns all authoritative state.

Responsibilities:

- validate settings;
- calculate allowed minutes from excluded ranges;
- create and clear `chrome.alarms`;
- handle `runtime.onInstalled`;
- handle `runtime.onStartup`;
- start a drafting session;
- inject content script;
- hold the central keystroke count;
- receive generic `keystroke` messages;
- update remaining count;
- reactivate drafted tab on attempted tab escape;
- reopen a prematurely closed drafted tab;
- complete/discharge session;
- schedule the next session.

The content script should remain disposable. Reloading the page must not reset progress because the numeric state lives in the service worker/session storage.

## 12. Scheduling algorithm

A simple implementation is sufficient.

Pseudo-code:

```text
scheduleNextDraft():
  clear existing DRAFTED alarm

  if disabled or target URL missing:
    return

  if lastDraftDate == today:
    date = tomorrow
  else:
    date = today

  loop:
    eligibleMinutes = all minutes on date
                      minus excluded ranges
                      minus minutes before now when date == today

    if eligibleMinutes is not empty:
      chosen = random(eligibleMinutes)
      create alarm at chosen
      return

    date = date + 1 day
```

When the alarm fires, re-check that the current local time is still permitted. If settings changed or the time is now excluded, reschedule instead of drafting.

Minute-level randomness is enough for v1.

---

## 13. Message protocol

Keep messages tiny and content-free.

Examples:

```js
{ type: "DRAFTED_READY" }
{ type: "KEYSTROKE" }
{ type: "SHOW_WARNING", remaining: 173 }
{ type: "UPDATE_REMAINING", remaining: 172 }
{ type: "DISCHARGED" }
```

No message should contain typed text.

---

## 14. State machine

```text
UNCONFIGURED
    │ save valid settings
    ▼
ARMED
    │ random alarm
    ▼
DRAFTED
    │ quota reached
    ▼
DISCHARGED
    │ schedule next eligible day
    ▼
ARMED
```

`DISARMED` is an explicit user setting and can be entered from any non-active state.

Disabling the extension during an active session naturally ends enforcement.

---

## 15. Visual tone

DRAFTED should look more like a tiny absurd system alert than a wellness/productivity product.

Core copy:

```text
YOU HAVE BEEN DRAFTED
300 KEYSTROKES TO DISCHARGE
```

During escape attempt:

```text
YOU ARE STILL DRAFTED
173 KEYSTROKES TO DISCHARGE
```

At completion:

```text
DISCHARGED.
```

Avoid motivational copy such as:

- You can do it!
- Keep going!
- Great job!
- Build your streak!

The joke is that the extension is bureaucratically indifferent to literary quality.

---

## 16. Privacy and safety requirements

These are requirements, not future improvements.

- No analytics.
- No telemetry.
- No remote server.
- No external API calls.
- No document parsing.
- No storage of key identities.
- No clipboard access.
- No reading browser history.
- No attempt to lock the operating system.
- No attempt to defeat Chrome's extension-disable controls.

The repository should be auditable by an ordinary developer.

---

## 17. Non-goals for v1

Do not implement unless the MVP proves useful:

- multiple manuscript URLs;
- multiple ambushes per day;
- weekly schedules;
- different quotas by day;
- streaks or achievements;
- word counting;
- character counting;
- productivity statistics;
- cloud sync;
- accounts;
- mobile support;
- Firefox/Safari ports;
- AI coaching;
- writing prompts;
- Chrome Web Store publishing;
- automatic updates.

---

## 18. Acceptance criteria

The MVP is done when all of the following are true:

1. A user can install the extension with **Load unpacked** from a GitHub download.
2. A user can save a Google Docs URL, keystroke quota, and multiple excluded ranges.
3. The extension schedules one random activation outside excluded hours.
4. The target document opens automatically when activated.
5. The exact intro text is displayed with the configured quota.
6. Pressing Space repeatedly can legally complete the quota.
7. The quota survives target-page reloads and drafted-tab reopening during the same Chrome session.
8. Switching to another tab before discharge returns the user to the drafted tab.
9. Closing the drafted tab before discharge reopens it without resetting progress.
10. Reaching the quota releases tab enforcement and displays `DISCHARGED.`
11. The extension never stores or transmits the contents of pressed keys or the manuscript.
12. Excluded hours are respected even after Chrome restart or settings changes.
13. Google Docs works in a real manual test.
14. The repository includes clear manual installation instructions and the MIT license.

---

## 19. First implementation order

1. `manifest.json` + settings persistence
2. manual `TEST DRAFT NOW`
3. open target tab + overlay/HUD
4. central keystroke counter
5. discharge at quota
6. tab-switch return behavior
7. drafted-tab reopen behavior
8. excluded-range parser
9. random daily alarm scheduling
10. optional host permission flow
11. Google Docs compatibility hardening
12. installation documentation cleanup

Build the coercive loop before polishing the scheduler. If the core joke is not fun in manual testing, do not add infrastructure around it.
